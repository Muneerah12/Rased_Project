## 1. التشغيل السريع

### ويندوز
1. ثبّت **Python 3.10 أو أحدث** من python.org، وفعّل خيار *Add Python to PATH* أثناء التثبيت.
2. حمّل المشروع:
   ```
   git clone https://github.com/Muneerah12/Rased_Project.git
   cd Rased_Project
   ```
3. سوّ الملفين السريين `CPS-Project/.env` و `server/.env` (الطريقة في [القسم 6](#6-الحساس-node-04-وخادم-cps)).
4. اضغط مرتين على **`start-cps.bat`**. يشغّل خادم CPS (8001) وخادم راصد (8010) مع بعض.
   - تبي الكاميرات والذكاء الاصطناعي بس، بدون CPS؟ استخدم **`start.bat`** وتقدر تتخطى الخطوة 3.
5. أول مرة يثبّت المكتبات ويأخذ عدة دقائق. بعدها يفتح المتصفح على **http://localhost:8010** تلقائياً.

### لينكس / ماك
```bash
./start.sh
```

**ما تحتاج Node.js.** الواجهة مبنية وجاهزة داخل `web/dist`.

> **أول تشغيل:** الموديلات تتنزل تلقائياً (تقريباً 1 إلى 2 جيجا)، فخل الإنترنت شغال. حالة كل موديل تظهر في صفحة «الكاميرات والذكاء الاصطناعي». لو فشل التنزيل يشتغل بديل مبني على OpenCV بدقة أقل، والصفحة توضح ذلك.

> **كرت شاشة NVIDIA:** التثبيت العادي على ويندوز يجيب نسخة PyTorch للمعالج. لتسريع كبير ثبّت نسخة CUDA من pytorch.org داخل `server\.venv`. الصفحة تعرض `cuda` أو `cpu`.

الدليل الكامل خطوة بخطوة (الملفات السرية، ESP32، التحقق، حل المشاكل): [`RUN_FROM_ZERO.md`](RUN_FROM_ZERO.md).

## 2. فيديوهات تجربة تحليل الكاميرات

داخل مجلد **`samples/`** مقاطع جاهزة. تقدر تشغلها بنفسك وتشوف راصد وهو يحلل ويفتح الحوادث، بدون أي كاميرا حقيقية.

| الملف | وش فيه | وش المفروض يرصد راصد | الطريقة |
| --- | --- | --- | --- |
| `samples/fire_bin_crowd.mp4` | ساحة فيها ناس يمشون، وحاوية نفايات تطلع منها نار ودخان | عدّ الأشخاص + **دخان** + **حريق** ← حادثة للدفاع المدني | أ |
| `samples/fire_shop_smoke.mp4` | ساحة فيها ناس، ونار ودخان يطلعون من محل | عدّ الأشخاص + **دخان** ثم **حريق** ← حادثة للدفاع المدني | أ |
| `samples/weapon_gunfire.mp4` | جنود يطلقون نار بأسلحة في ساحة تدريب، مع صوت الإطلاق | **سلاح** + **صوت إطلاق نار** ← حادثة لفريق الأمن | ب |
| `samples/crowd_indoor_event.mp4` | قاعة فعالية مليانة جمهور جالس | **عدّ الأشخاص** + **ازدحام** لو العدد تجاوز «السعة» ← حادثة لمنظمي إكسبو | أ |
| `samples/test_scene.mp4` | مشهد قصير فيه أشخاص ولهب (بدون صوت) | عدّ الأشخاص + **حريق** | أ |

> **تجربة الازدحام:** قبل تشغيل `crowd_indoor_event.mp4` اضغط زر **«السعة»** في مربع الكاميرا وحط رقم صغير (مثلاً 10)، عشان العدد يتجاوزه وتنفتح حادثة الازدحام.

### الطريقة أ: تشغيل الفيديو كأنه بث كاميرا مباشر
تستخدمها للحريق والدخان والعدّ والسقوط والازدحام.

1. شغّل المنصة وافتح **http://localhost:8010**.
2. من القائمة افتح صفحة **«الكاميرات والذكاء الاصطناعي»**.
3. في مربع أي كاميرا اضغط زر **«إرفاق فيديو»** (أيقونة السهم للأعلى).
4. اختر ملف من مجلد `samples/`، مثلاً `fire_bin_crowd.mp4`.
5. الفيديو يشتغل ويتكرر، وتشوف عليه مربعات الكشف (برتقالي للحريق، رمادي للدخان).
6. خلال ثواني تنفتح الحادثة: يطلع تنبيه وصوت، وتلقاها في صفحة **«الحوادث»** ومعها اللقطة.
7. للإيقاف اضغط زر **«إيقاف»** في نفس مربع الكاميرا.

### الطريقة ب: رصد التهديدات في فيديو مسجّل
تستخدمها للأسلحة وأصوات إطلاق النار والشجار والركض المفاجئ.

1. في نفس صفحة **«الكاميرات والذكاء الاصطناعي»** انزل لبطاقة **«رصد التهديدات في فيديو»**.
2. اضغط **«اختر ملف فيديو»** واختر `samples/weapon_gunfire.mp4`.
3. من **«ينسب إلى»** اختر الكاميرا اللي تبي الحادثة تنحسب عليها.
4. اضغط **«تحليل بالذكاء الاصطناعي»**، وانتظر لين تخلص المراحل: **الصوت** و**الفيديو (سلاح + سلوك)**.
5. تطلع النتائج على خط زمني: نوع التهديد، الوقت داخل الفيديو، نسبة الثقة، واللقطة.
6. اضغط **«عرض في الفيديو»** عشان تروح للحظة الرصد، أو **«فتح الحادثة»** عشان تشوف الحادثة.
7. زر **«تقرير الحادثة»** يطلع تقرير جاهز للطباعة.

> **ملاحظات**
> - البطاقة تشتغل لدور **المشغل** أو **المحلل** فقط. لو طلعت لك رسالة إنها غير متاحة، غيّر الدور من أعلى الصفحة.
> - تقدر تجرب **أي فيديو عندك** بنفس الطريقتين. الصيغ المقبولة: MP4 و AVI و MOV و MKV و WEBM.
> - لو شغلت نفس الفيديو مرة ثانية والحادثة لسا مفتوحة، ما تنفتح حادثة جديدة. الرصد الجديد ينضاف للحادثة نفسها كدليل. تبي تبدأ من الصفر؟ شوف «البدء من جديد» في [القسم 8](#8-أدوات-إضافية).
> - على المعالج (بدون كرت شاشة) التحليل أبطأ، والطريقة ب ممكن تأخذ دقيقة أو أكثر.

## 3. ربط الكاميرات

كل مربع كاميرا في صفحة «الكاميرات والذكاء الاصطناعي» له ثلاث طرق ربط:

| الزر | متى تستخدمه |
|---|---|
| **إرفاق فيديو** | تجربة بملف فيديو يتكرر (فيديوهات `samples/` في القسم 2). |
| **كاميرا الجهاز** | كاميرا اللابتوب أو كاميرا USB على الجهاز اللي فاتح الصفحة. |
| **ربط كاميرا IP / RTSP** | كاميرات المراقبة وأجهزة التسجيل NVR. السيرفر نفسه يحلل حتى لو المتصفح مقفل، وفيه خيار «يبدأ تلقائياً مع الخادم». |

### أمثلة روابط RTSP

| النوع | الرابط |
|---|---|
| Hikvision | `rtsp://user:pass@192.168.1.64:554/Streaming/Channels/101` |
| Dahua | `rtsp://user:pass@192.168.1.108:554/cam/realmonitor?channel=1&subtype=0` |
| كاميرا USB على جهاز السيرفر | اكتب `0` أو `1` |

### إعدادات كل كاميرا
- **الكواشف:** عدّ الأشخاص، الدخان، الحريق، السقوط، اتجاه المشي.
- **اتجاه المشي الصحيح:** يظهر لما تفعّل كاشف اتجاه المشي.
- **سعة المنطقة** (زر «السعة»): حد الازدحام. لما يتجاوزه العدد تنفتح حادثة «ازدحام».

> المتصفح يسمح بالكاميرا فقط على `localhost` أو `https`. يعني كاميرا الجهاز تشتغل من نفس جهاز السيرفر، أما الأجهزة الثانية فاستخدم معها RTSP.

## 4. الحوادث والتحليلات

```
كاميرا / فيديو / RTSP ─► موديلات الذكاء الاصطناعي ─► رصد متكرر ─► حدث ─► تنبيه + حادثة + لقطة ─► إشعار الفريق المختص
                                                                               │
                                                               كل شاشات راصد المفتوحة (مباشر)
```

### ألوان مربعات الكشف

| اللون | المعنى |
|---|---|
| أخضر | اتجاه صحيح |
| أحمر | عكس الاتجاه أو سقوط |
| أصفر | يتتبع |
| برتقالي | حريق |
| رمادي | دخان |

### متى تنفتح الحادثة
الحدث ما ينفتح إلا إذا تكرر الرصد في **3 من آخر 5 إطارات**، عشان ما تطلع حوادث من إطار واحد غلط. ولما يختفي الرصد **8 ثواني** ينتهي الحدث.

### وش فيها الحادثة
- لقطة محفوظة عليها المربعات.
- نسبة الثقة واسم الموديل.
- الإشعارات اللي انرسلت.
- مسار الاستجابة كامل: تكليف ← قبول ← في الطريق ← وصول ← معالجة ← إغلاق.

### المشاركة بين الشاشات
كل الشاشات تشوف نفس الحوادث بنفس الأرقام، والتكليف من شاشة المشغل يظهر عند المستجيب. البيانات تبقى بعد تحديث الصفحة وبعد إعادة تشغيل السيرفر، ومحفوظة في `server/data/`.

### الأرقام في لوحة القيادة
عدد الأشخاص ومنحنى الحشود ومؤشر الازدحام كلها من العدّ الحقيقي لمصدر الكاميرا 1.

## 5. التنبيهات

| نوع الرصد | الفريق المختص |
|---|---|
| السقوط | الكادر الطبي |
| الحريق والدخان | الدفاع المدني |
| الازدحام والاتجاه الخاطئ | منظمو إكسبو |
| السلاح وإطلاق النار والسلوك غير الطبيعي | فريق الأمن |
| انقطاع الحساس NODE-04 | حادثة «IoT Sensor» في صفحة الحوادث |

### القنوات
1. **شاشات راصد:** شغالة دائماً. يطلع تنبيه وصوت ورسالة على الشاشة، وإشعار سطح المكتب لو فعّلته من زر «تفعيل الصوت وإشعارات سطح المكتب».
2. **Telegram:** يرسل صورة اللقطة مع نص عربي.
3. **Webhook:** يرسل الحدث كـ JSON لأي نظام، مثل بوابة SMS أو n8n أو Teams.

### إعداد القنوات في `server/.env`
الملف ينشأ تلقائياً من `.env.example` أول تشغيل.

```ini
TELEGRAM_BOT_TOKEN=123456:ABC...
TELEGRAM_CHAT_ID=-100xxxxxxxxxx
TELEGRAM_CHAT_ID_CIVIL_DEFENSE=-100yyyy   # اختياري: قروب لكل فريق
NOTIFY_WEBHOOK_URL=https://example.com/rasid-hook
RASID_PUBLIC_URL=http://192.168.1.10:8010 # يضيف رابط اللقطة في الرسالة
```

**طريقة إعداد Telegram:**
1. أنشئ بوت من **@BotFather**.
2. أضف البوت للقروب.
3. خذ رقم القروب، مثلاً من @RawDataBot.
4. أعد تشغيل المنصة.

بعدها جرّب زر «إشعار تجريبي». نتيجة كل إرسال (نجح أو فشل) تنسجل في الحادثة وتطلع في ملخص التقرير.

## 6. الحساس NODE-04 وخادم CPS

- **NODE-04** جهاز ESP32 عليه حساس BME280 (حرارة، رطوبة، ضغط) ومرحّل للتكييف، في المنطقة A1.1.
- يرسل نبضات وقراءات لـ **خادم CPS** على المنفذ 8001، وخادم CPS يحفظها في `CPS-Project/backend/cps.db`.
- **السجل التاريخي موجود داخل المستودع**، فأول ما تشغل تشوف القراءات والنبضات السابقة.
- خادم راصد يقرأ من CPS (قراءة فقط) ويعرض كل شيء في **لوحة راصد ← IoT / CPS**: نظرة عامة، OT، NOC، مركز المحاكاة.
- لو انقطع NODE-04 أكثر من 90 ثانية يطلع تنبيه وتنفتح حادثة «CPS Node Offline»، وتنقفل لحالها لما يرجع.

### الملفات السرية (ما تنرفع على GitHub أبداً)

| الملف | انسخه من | وش تحط فيه |
| --- | --- | --- |
| `CPS-Project/.env` | `CPS-Project/.env.example` | `ADMIN_PROVISIONING_TOKEN` و `RASID_INTEGRATION_TOKEN` و `RASID_CONTROL_TOKEN` (قيم عشوائية طويلة) |
| `server/.env` | `server/.env.example` | `CPS_RASID_INTEGRATION_TOKEN` = نفس قيمة `RASID_INTEGRATION_TOKEN`، و `CPS_INTEGRATION_BASE_URL=http://127.0.0.1:8001` |

تسوي قيمة عشوائية بهذا الأمر:
```
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

ربط جهاز ESP32 نفسه (الواي فاي، الشهادة، رفع البرنامج) موضح خطوة بخطوة في [`RUN_FROM_ZERO.md`](RUN_FROM_ZERO.md) القسم 6.
بدون الجهاز المنصة تشتغل عادي، وNODE-04 يطلع «غير متصل» مع السجل السابق.

## 7. الحقيقي والتجريبي

| الجزء | الحالة |
|---|---|
| الكاميرات، الكشف، العدّ، الأحداث، الحوادث، اللقطات، الإشعارات، التكليف والاستجابة | **حقيقي**، يشتغل على السيرفر |
| NODE-04 (الحرارة والرطوبة والضغط والنبضات) | **حقيقي** من جهاز ESP32 عبر خادم CPS |
| مركز المحاكاة | **محاكاة** للتجربة والعرض، ومكتوب عليه ذلك |
| العقد الأخرى، الطائرة المسيّرة، بيانات الموظفين، الحوادث السابقة (INC-0142/0143) | **بيانات تجريبية**، لأنه ما فيه لها مصدر حقيقي |
| تبديل الدور (مشغل / مستجيب…) | **معاينة للواجهة فقط**، وليس تسجيل دخول |

إذا فتحت راصد بدون السيرفر، ترجع الواجهة لوضع المحاكاة وتكتب أن الخادم غير متصل.

## 8. أدوات إضافية

### البدء من جديد
اضغط **Alt+Shift+D** ← «مسح السجل المشترك والبدء من جديد».

### ضبط الحساسية
من `server/.env`:

| المتغير | وظيفته |
|---|---|
| `RASID_EVENT_START_HITS` | كم مرة لازم يتكرر الرصد عشان يبدأ الحدث |
| `RASID_EVENT_END_AFTER_S` | كم ثانية بدون رصد عشان ينتهي الحدث |
| `RASID_EVENT_COOLDOWN_S` | أقل فاصل قبل حدث جديد من نفس النوع على نفس الكاميرا |
| `RASID_STREAM_MAX_FPS` | أقصى معدل تحليل لكل بث |

### تطوير الواجهة (يحتاج Node.js 20+)
```bash
cd web
npm install
npm run dev     # على 5173، ويحوّل /api إلى السيرفر على 8010
npm test        # الاختبارات
npm run build   # يحدّث web/dist
```

### واجهة API للرصد
- `POST /api/detect` يستقبل صورة ويرجع نتائج الرصد. أضف `camera_id` لما تبي الرصد يتحول لأحداث وحوادث.
- `POST /api/analyze-video` يستقبل ملف فيديو ويحلله كامل (نفس الطريقة ب).

## English summary

**Rased Platform** is this repository: one platform, one dashboard at http://localhost:8010.
The CPS backend (port 8001) runs in the background and is read only through the platform; there is
no separate CPS dashboard. Start with `start-cps.bat`; full guide in [`RUN_FROM_ZERO.md`](RUN_FROM_ZERO.md).
A hosted copy runs at https://rased-ivory.vercel.app (dashboard on Vercel, server and models on the Hugging Face
Space `Ahmed014/rased`); see [`deploy/README.md`](deploy/README.md).

**Two ways to see it:** the demo website **https://rased-ivory.vercel.app/** (a real website with
fake demo data, nothing to install), or run it locally on your PC (real camera analysis and NODE-04
data). Sign in to either with username **`admin`** and password **`admin12345`** (a demo sign-in,
not real access control).

**Demo videos** are in `samples/`. In *Cameras & AI*, use a camera tile's **Attach video** button to
play `fire_bin_crowd.mp4`, `fire_shop_smoke.mp4`, `crowd_indoor_event.mp4` or `test_scene.mp4` as a
looping live feed (people count, crowding, smoke, fire). Use the **Threat detection in a video** card for `weapon_gunfire.mp4` (weapons,
gunshot audio, abnormal behavior). Each detection opens an incident with a snapshot.

**Before a live demo**, check `/api/health`, `/api/cps/node-state` and
`/api/operational/hvac/recommendation` on the RASID server. Confirm NODE-04 has a current heartbeat
and camera observations are fresh. An unavailable, stale or offline source stays labelled as such
and never falls back to simulation data. The operational HVAC endpoint is monitor-only: without an
approved threshold policy it returns `POLICY_NOT_CONFIGURED` and sends no fan command.
